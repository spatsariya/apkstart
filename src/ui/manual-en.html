ApkStart User Guide and Troubleshooting

ApkStart lets you install Android APK files on Windows, launch apps using their own desktop shortcuts, and run apps in independently managed windows. This guide describes setup, common tasks, and practical fixes.

Platform: Windows 10/11 x64. Project: RoutineMiku/apkstart. Fork: spatsariya/apkstart.

1. ApkStart in 30 seconds

  1. Install the APK installer or extract the portable edition.
  2. Run ApkStart and complete Android runtime setup if asked.
  3. Drag an .apk file into ApkStart, or choose Install APK.
  4. Launch the installed app using its desktop or Start menu shortcut.
  5. Use F11 for fullscreen and open Settings to adjust controls and performance.

2. Installation and first launch

The full portable, installer, and MSIX builds can contain a complete runtime. The lightweight portable download fetches the Android Emulator and system image at first use.

Releases: GitHub or Gitee.

On first launch, select One-click setup when needed. Wait for adb, Android Emulator, and the Android 14 system image to be ready. An initial Android boot may take several minutes on slower systems.

2.2 What happens on first launch

The app checks whether Android tools, a system image, and hardware acceleration are available. When necessary, it downloads components and prepares an Android virtual disk. Your Android data, installed apps and snapshots are stored outside the portable program directory.

3. Everyday usage

Use the Install APK button, drag and drop an APK, or enable the Windows .apk file association to install by double-clicking a file.

3.1 Installing apps

APK packages are inspected locally, installed through adb, and added to the application grid. For split packages such as .apks or .xapk, use the supported package workflow. If an ARM-only application fails, check compatibility mode and the Android 14 Google Play image.

3.2 Launching apps

Double-click the app in ApkStart or its Windows shortcut. Android may start in the background. Subsequent launches usually reuse the running environment. Right-click an app to open its context menu, create a shortcut, adjust orientation, clear app data, or uninstall.

3.3 Windows, orientation and display

Each app is presented as its own Windows window. You can choose portrait or landscape, auto fullscreen and tablet layout in Settings → Display & Windows. The app tries to match the virtual panel orientation to the requested application orientation.

Changes to the virtual screen's physical orientation may restart the Android runtime. Press F11 to toggle fullscreen.

3.5 Shared folders between Windows and Android

The default Windows folder is %USERPROFILE%\ApkStartShared, paired with /sdcard/ApkStartShared inside Android. ApkStart synchronizes the folders in both directions. It is a synchronization service, not a direct disk mount.

3.6 Finding settings

Open Settings from the top right of the main window. Categories include General & Installation, Display & Windows, Controls & Input, Performance & Resources, Network & Downloads, Diagnostics & Repair, Integration & Files, and Updates & About. Search for a setting using the search field at the top.

App Language changes ApkStart's own interface without changing Android guest language. Android system language is a separate setting and takes effect after restarting Android.

3.7 Updating

Use Settings → Updates & About → Check for updates. The updater evaluates available sources and mirrors. Updating the program normally retains Android user data, downloaded runtime files and snapshots.

4. Runtime, acceleration and ARM compatibility

Runtime: The Android Emulator, adb, and an Android system image.

Acceleration: WHPX or Google AEHD can significantly speed up Android boot and rendering. Software fallback is much slower.

ARM compatibility: Some ARM-only apps work through the translation layer in the Android 14 Google Play system image. Apps that check for real device sensors, cellular hardware or emulator status may still fail.

5. Check the system first

Before troubleshooting manually, open Settings → Diagnostics & Repair and run the environment check. Follow the suggested repair actions. Export a diagnostic report if the problem continues.

5.1 Preflight and automatic configuration

The preflight system checks CPU virtualization, Windows hypervisor features, GPU, RAM, drivers, and operating system compatibility. Settings that can safely be adjusted are applied or suggested; BIOS-only changes require manual action.

5.2 Automatic diagnostics and network repair

Background diagnostics check failed boots, invalid snapshots, adb connectivity, disk pressure, incompatible settings, and Android internet access. You can disable checks or change the interval in Settings. For an Android network failure, choose Repair network.

5.3 Exporting a report

Select Export diagnostic report from the troubleshooting settings. Include the report and a description of the steps to reproduce your problem when opening an issue.

5.4 Context-sensitive help

Diagnostic alerts may open this guide at a relevant section. The help icon in the app header opens the full manual.

6. Troubleshooting common issues

Choose a topic below for specific steps. If you cannot resolve an issue, collect a diagnostic report and the last few lines of app.log.

6.1 Hardware acceleration disabled / Android boots slowly

ApkStart can use Windows Hypervisor Platform (WHPX) or the Android Emulator Hypervisor Driver (AEHD). Open Diagnostics & Repair → Repair. If using the MSIX edition, Windows may require you to enable WHPX yourself.

  1. Open Turn Windows features on or off.
  2. Select Windows Hypervisor Platform.
  3. Confirm and restart the PC.
  4. Run the app's environment check again.

You can also run PowerShell as administrator:

dism /online /enable-feature /featurename:HypervisorPlatform /all /norestart
dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

Important: Virtual Machine Platform alone is not equivalent to Windows Hypervisor Platform.

6.2 APK installation failed (INSTALL_FAILED_*)

ErrorAction
INSTALL_FAILED_INSUFFICIENT_STORAGEFree disk space or increase the Android data partition.
INSTALL_FAILED_NO_MATCHING_ABISTry Android 14 ARM compatibility support; some apps are not compatible.
INSTALL_FAILED_UPDATE_INCOMPATIBLEBack up data, uninstall the app with a conflicting signature, and reinstall.
INSTALL_FAILED_VERSION_DOWNGRADERemove the higher installed version before installing an older one.
Corrupted or incomplete APKDownload a valid installer from a trustworthy source and retry.

6.3 ARM translation missing / ARM-only app crashes

Use the Android 14 Google Play system image that includes the translation layer. Confirm that the runtime and image are current. If a particular app detects an emulator or requires physical device hardware, it may still fail even if the installation succeeds.

6.4 adb unauthorized or offline

ApkStart uses adb server port 5044 rather than the default port 5037. In PowerShell:

$env:ANDROID_ADB_SERVER_PORT = 5044
adb devices

If prompted to allow USB debugging, approve it inside Android. Otherwise, use Diagnostics → Restart runtime. Avoid manually connecting to port 5555, which may trigger unexpected authorization prompts.

6.5 Shortcut does nothing / spinner / unexpected window

  1. Check whether the Android runtime is installed and running.
  2. Try launching from within ApkStart instead of the desktop shortcut.
  3. Run Diagnostics & Repair; clear stale locks or restart the runtime when advised.
  4. Use Rebuild shortcuts if shortcut icons or paths are incorrect.
  5. If an app window is blank, try the default Native window rendering mode and check graphics acceleration.

6.6 Other startup issues

SymptomSuggested fix
Stuck boot / blank screenRestart runtime, clear a broken snapshot, review acceleration and GPU mode.
No Android device foundCheck adb on port 5044 and runtime state.
Disk space warningClean removable files or relocate runtime/data folders.
Incorrect orientationUse per-app orientation override and reopen the app.
Wrong shortcut iconSettings → Integration & Files → Rebuild shortcuts.

6.7 No sound / quiet audio

Ensure Android audio is enabled in ApkStart's settings. Check Windows volume mixer, default audio output, and the Android media volume. Restart the runtime after changing audio settings. Windows Audio service must be running.

6.8 Store edition fails with 0xC0000135 or missing DLL

This usually indicates a missing Microsoft Visual C++ runtime or related dependency. Install the official Microsoft Visual C++ Redistributable (x64), restart if required, and try again.

6.9 Microphone unavailable

Enable Microphone input in ApkStart's performance settings and restart the Android runtime. Check Windows microphone permissions, microphone device selection, and application-level permissions inside Android.

6.10 Choosing discrete vs integrated graphics

If you have both an integrated GPU and a dedicated GPU, select the preferred option under Performance & Resources → Preferred GPU. Changes may require restarting the Android emulator to take effect.

7. Command-line reference

ApkStart.exe                         Open ApkStart
ApkStart.exe <path\to\app.apk>      Install an APK
ApkStart.exe --launch <package>       Launch installed app

9. Getting help and reporting issues

Include the diagnostic report, the last 20 lines of your runtime log, and your exact ApkStart version/distribution when reporting a bug.
